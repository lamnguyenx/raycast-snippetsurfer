# Multiple Snippet Locations with Hotkeys

**Date**: 2026-01-26
**Version**: 01
**Status**: Draft (Execution planned)

## Problem Statement

Currently, SnippetSurfer supports multiple snippet folders, but they are all merged into a single search command (`shift+space`). Users who maintain separate snippet collections (e.g., work vs. personal, project-specific vs. general) want the ability to:

1. Define distinct snippet locations
2. Assign unique hotkeys to each location
3. Search/access snippets from a specific location without changing filters or preferences

## Proposed Solution

Create a multi-command architecture where each snippet location has its own dedicated command with configurable hotkey.

### Key Features

- **Multiple Commands**: Each snippet location gets its own Raycast command
- **Hotkey Customization**: Unique hotkey per command (e.g., `shift+1`, `shift+2`, `cmd+1`, etc.)
- **Isolated Search**: Each command searches only its designated folder(s)
- **Shared Configurations**: Common settings (file extensions, preview lines) shared across all commands
- **Dynamic Preferences**: Support for adding/updating snippet locations without code changes

```json
    // ... existing shared preferences ...
  ]

```

### 2. Dynamic Command Registration

Instead of hardcoding commands, use a dynamic approach:

```typescript
export const commands: Command[] = [
  createSnippetCommand({
    name: "search-snippets",
    title: "Search Snippets (Primary)",
    hotkey: "shift+space",
    folderName: "primary",
  }),
  createSnippetCommand({
    name: "search-work-snippets",
    title: "Work Snippets",
    hotkey: "shift+1",
    folderName: "work",
  }),
];

function createSnippetCommand(config: SnippetCommandConfig) {
  return {
    name: config.name,
    title: config.title,
    description: `Search snippets from ${config.title} folder`,
    mode: "view" as const,
    hotkey: config.hotkey,
    preferences: [
      {
        name: "folderPath",
        type: "directory",
        required: true,
        title: `${config.title} Folder`,
      },
    ],
  };
}
```

_Use a build-time script to generate the commands array based on user preferences or hardcoded locations._

### 3. Configuration System

Add a new preference type for snippet locations:

```typescript
interface SnippetLocation {
  name: string;
  path: string;
  hotkey?: string;
  isPrimary?: boolean;
}

interface Preferences {
  snippetLocations: SnippetLocation[];
  supportedExtensions: string;
  searchIndexLines: string;
  primaryAction: string;
}
```

### 4. Shared Component Architecture

Create a single, reusable search component:

```typescript
interface SnippetSearchProps {
  locationName: string;
  folderPath: string;
  primaryAction: string;
  searchIndexLines: number;
  supportedExtensions: string[];
}

export default function SnippetSearch({ locationName, folderPath, primaryAction, ...props }: SnippetSearchProps) {
  // Already implemented in search-snippets.tsx
  // Just needs to accept location-specific props
}
```

### 5. Dynamic Route Handling

Create command files that dynamically import the shared component:

```typescript
// src/commands/search-work-snippets.tsx
import SnippetSearch from "../shared/SnippetSearch";
import { getPreferenceValues } from "@raycast/api";

export default function Command() {
  const preferences = getPreferenceValues();

  return (
    <SnippetSearch
      locationName="Work"
      folderPath={preferences.folderPath}
      primaryAction={preferences.primaryAction}
      searchIndexLines={parseInt(preferences.searchIndexLines || "3")}
      supportedExtensions={preferences.supportedExtensions.split(",")}
    />
  );
}
```

## Implementation Plan

### Phase 1: Setup Infrastructure

1. **Create shared component structure**

   - Extract core search logic from `search-snippets.tsx` into reusable components
   - Create `shared/SnippetSearch.tsx` with location-specific props
   - Update types to support location awareness

2. **Add new preference types**

   - Add `snippetLocations` preference for managing locations
   - Maintain backward compatibility with existing preferences

3. **Update manifest structure**
   - Add three hardcoded commands initially (Primary, Work, Personal)
   - Set up hotkeys `shift+space`, `shift+1`, `shift+2`

### Phase 2: Dynamic Binding

1. **Create command template**

   - Make `SnippetSearch` fully reusable with dynamic props
   - Support per-location configuration overrides

2. **Build command generator**

   - Create a script to generate command files from configuration
   - Or use TypeScript template literals for build-time generation

3. **Shared state management**
   - Implement LRU cache that's shared across all commands
   - Add location identifier to cache keys
   - Optimize memory usage by avoiding duplicate file previews

### Phase 3: User Experience

1. **Configuration UI**

   - Add an "Add New Location" action in settings
   - Allow assigning hotkeys through Raycast's native command hotkey settings
   - Provide clear documentation on hotkey conflicts

2. **Visual distinctions**

   - Different folder icons for different locations
   - Location-specific subheaders in search results
   - Clear folder path indicators

3. **Shared settings**
   - Keep `supportedExtensions`, `searchIndexLines`, and `primaryAction` global
   - Allow per-location overrides via advanced settings

### Phase 4: Polish & Testing

1. **Performance optimization**

   - Cache discovery results per location
   - Implement parallel loading for multiple locations
   - Add loading indicators for concurrent searches

2. **Error handling**

   - Graceful handling of invalid folder paths
   - Clear error messages for hotkey conflicts
   - File system permission warnings

3. **Testing**
   - Backward compatibility testing
   - Hotkey conflict scenarios
   - Large file handling across multiple locations
   - Memory leak testing with multiple locations

## Backward Compatibility

- Existing `folderPath` and `secondaryFolderPaths` preferences are deprecated but still supported
- Migration script converts existing configuration to new format
- Default behavior: Primary command merges all existing folders
- Users continue using `shift+space` as before

## Risk Mitigation

### Technical Risks

- **Hotkey Conflicts**: Validate hotkeys during configuration
- **Memory Management**: Strict LRU cache limits per location
- **Code Duplication**: Enforce shared component pattern

### User Experience Risks

- **Configuration Complexity**: Provide clear migration path
- **Feature Discovery**: Add in-app documentation and tooltips
- **Hotkey Learning Curve**: Use visual feedback for hotkey assignment
