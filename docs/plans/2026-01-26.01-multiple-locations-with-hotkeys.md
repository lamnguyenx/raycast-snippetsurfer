# Multiple Snippet Locations with Hotkeys

**Date**: 2026-01-26
**Version**: 01
**Status**: Draft (Execution planned)

## Problem Statement

Currently, SnippetSurfer supports multiple snippet folders, but they are all merged into a single search command (`shift+space`). Users who maintain separate snippet collections (e.g., work vs. personal, project-specific vs. general) want the ability to:

1. Define distinct snippet locations
2. Assign unique hotkeys to each location
3. Search/access snippets from a specific location without changing filters or preferences

## Proposed Solution

Create a multi-command architecture where each snippet location has its own dedicated command with configurable hotkey.

### Key Features

- **Multiple Commands**: Each snippet location gets its own Raycast command
- **Hotkey Customization**: Unique hotkey per command (e.g., `shift+1`, `shift+2`, `cmd+1`, etc.)
- **Isolated Search**: Each command searches only its designated folder(s)
- **Shared Configurations**: Common settings (file extensions, preview lines) shared across all commands
- **Dynamic Preferences**: Support for adding/updating snippet locations without code changes

### 2. Dynamic Command Registration

Instead of hardcoding commands, use a dynamic approach:

```typescript
export const commands: Command[] = [
  createSnippetCommand({
    name: "search-snippets",
    title: "Search Snippets (Primary)",
    hotkey: "shift+space",
    folderName: "primary",
  }),
  createSnippetCommand({
    name: "search-work-snippets",
    title: "Work Snippets",
    hotkey: "shift+1",
    folderName: "work",
  }),
];

function createSnippetCommand(config: SnippetCommandConfig) {
  return {
    name: config.name,
    title: config.title,
    description: `Search snippets from ${config.title} folder`,
    mode: "view" as const,
    hotkey: config.hotkey,
    preferences: [
      {
        name: "mainFolderPath",
        type: "directory",
        required: true,
        title: `${config.title} Folder`,
      },
    ],
  };
}
```

_Use a build-time script to generate the commands array based on user preferences or hardcoded locations._

### 3. Configuration System

Add a new preference type for snippet locations:

```typescript
interface SnippetLocation {
  name: string;
  path: string;
  hotkey?: string;
  isPrimary?: boolean;
}

interface Preferences {
  snippetLocations: SnippetLocation[];
  supportedExtensions: string;
  searchIndexLines: string;
  primaryAction: string;
}
```

### 4. Shared Component Architecture

Create a single, reusable search component:

```typescript
interface SnippetSearchProps {
  locationName: string;
  mainFolderPath: string;
  primaryAction: string;
  searchIndexLines: number;
  supportedExtensions: string[];
}

export default function SnippetSearch({ locationName, mainFolderPath, primaryAction, ...props }: SnippetSearchProps) {
  // Already implemented in search-snippets.tsx
  // Just needs to accept location-specific props
}
```

### 5. Dynamic Route Handling

Create command files that dynamically import the shared component:

```typescript
// src/commands/search-work-snippets.tsx
import SnippetSearch from "../shared/SnippetSearch";
import { getPreferenceValues } from "@raycast/api";

export default function Command() {
  const preferences = getPreferenceValues();

  return (
    <SnippetSearch
      locationName="Work"
      mainFolderPath={preferences.mainFolderPath}
      primaryAction={preferences.primaryAction}
      searchIndexLines={parseInt(preferences.searchIndexLines || "3")}
      supportedExtensions={preferences.supportedExtensions.split(",")}
    />
  );
}
```
